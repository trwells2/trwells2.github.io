Every swing leaves a track. This reads them.

Overview

A simulator makes data. Spreadsheets don’t make sense of it.

A golf simulator records every shot: club, carry, total, offline, ball speed. After a few sessions that is thousands of rows in a sheet, and a sheet can tell you your average 7-iron. It cannot tell you which club you can actually trust on a given shot.

GSPro Shot Analytics answers that question. Shots are colour-coded by club and plotted as dispersion, so the shape of a miss is visible rather than averaged away. A distance-weighted consistency metric ranks clubs by how tightly they group relative to how far they carry, which is the comparison a raw standard deviation gets wrong.

It is the same pattern as the federal work, at hobby scale: a messy source, one model over it, and a surface that answers a question. That is why it is on this site.

Process

How it was built.

Six stages, from a session log to a dashboard that loads in a browser tab.

  1. 01

    Get the shots out of the simulator

    Session data lands in Google Sheets, which is the right store for this: free, editable by hand when a shot needs correcting, and already synced. Python collects and normalises the rows on a schedule, with retry and resume logic so an interrupted run does not duplicate or lose a session.

  2. 02

    Normalise the record

    Club names, units and outliers are reconciled into one consistent shape before anything reads them, so a 7-iron logged three different ways is still one club. Structured logging makes a bad session traceable rather than mysterious.

  3. 03

    Put a Worker in front of the key

    A Cloudflare Worker at api.trwells.com proxies the Google Sheets API. The browser talks to the Worker; the Worker holds the credential. Nothing sensitive ships to the client, and the front end stays a static file on GitHub Pages.

  4. 04

    Build the dashboard

    React and Recharts in a single self-contained page: club-colour-coded dispersion and distance views, a paginated shot feed for reading individual swings, and CSV export for anything the dashboard does not answer.

  5. 05

    Define the consistency metric

    Grouping tightness means little without distance: a wedge and a driver cannot be compared on spread alone. The distance-weighted consistency score normalises for carry, so clubs can be ranked against each other and tracked over time.

  6. 06

    Ship it and keep using it

    Deployed on GitHub Pages at trwells.com/gspro and refined against real sessions since. Every change has to survive the only user who matters: the one standing on the mat wondering which club to hit.

Results

What it does.

●

Shows the shape of a miss

Club-coloured dispersion makes a two-way miss look different from a consistent fade. An average hides that; a scatter does not.

1

One number per club

The distance-weighted consistency score ranks clubs on a single comparable scale, so practice goes where the spread actually costs strokes.

0

Credentials in the client

The Cloudflare Worker keeps the Google Sheets key server-side. The published page is a static file with nothing to leak.

CSV

An exit door

Every filtered view exports to CSV, so a question the dashboard does not answer can still be answered somewhere else.

Stack

Stack breakdown.

  • ReactThe application, built as a single self-contained page — no build step, no framework scaffolding to maintain.
  • RechartsDispersion, distance and trend charts, with club colour coding carried consistently across every view.
  • Cloudflare WorkersThe API layer at api.trwells.com: proxies Google Sheets so the key stays server-side and responses stay fast.
  • Google Sheets APIThe live data source. Editable by hand when a logged shot is wrong, which a database would make tedious.
  • PythonCollection and normalisation on a schedule, with retry and resume logic and structured logging.
  • GitHub PagesHosting for the dashboard and this site, deployed from the repo with no server to keep alive.
